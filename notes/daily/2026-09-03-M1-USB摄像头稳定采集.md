# 日期

2026-09-03

## 今日目标

- 完成 M1 USB 摄像头枚举、可配置采集和稳定性验证，不进入轮廓识别。

## 今日环境

- 电脑：主开发电脑
- OS：Windows 11 家庭版 中文版，64 位，Build 26200
- Python 版本：3.12.10
- 被测 Git commit：`d2b864d852e3910ba10a6572c0bd98bb8249a9f0`
- 摄像头：Insta360 Ace Pro 2；另检测到内置 USB2.0 HD UVC WebCam
- 控制器通信：未使用
- 光照/实验条件：室内自然光与照明；未使用三脚架垂直俯拍，未铺设 A3 白色背景

## 今天做了什么

1. 阅读 `AGENTS.md`、`docs/PROJECT_SPEC.md` 和 `docs/ROADMAP.md`，确认只做 M1。
2. 使用 Windows PnP 枚举硬件，确认 Insta360 Ace Pro 2 和内置摄像头状态为 OK。
3. 建立 `.venv`，安装并锁定 OpenCV、NumPy、pytest 和摄像头枚举依赖。
4. 用 DirectShow 验证 Insta360 默认采集，并探测 720p、1080p、4K 请求行为。
5. 实现按名称优先选择设备的配置、采集、JSON 报告与 CLI。
6. 编写配置、设备选择和 CLI 回归测试。
7. 修复枚举命令的 `duration` 属性异常。
8. 提交可测试代码后，执行 3 秒烟雾测试和 60 秒正式稳定性测试。
9. 逐项核对 JSON、代表帧和验收门槛。

## 修改内容

- 新增 `pc/camera/` 采集模块和命令行入口。
- 新增 `pc/config/camera.json`，设备名称、后端、分辨率、帧率和门槛均可配置。
- 新增 13 项自动化测试。
- 新增并锁定 `requirements.txt`。
- 更新 README 的 M1 运行命令。

## 测试过程

1. 单元/回归测试：`python -m pytest -q`。
2. CLI 枚举：确认 Insta360 名称和当前索引。
3. 模式预探测：默认、720p、1080p、4K 请求。
4. 3 秒烟雾测试。
5. 60 秒连续采集及 3 次重新打开测试，详见 [[TEST-001-M1-Insta360稳定采集]]。

## 实际测试结果

- 自动化测试 13/13 通过。
- 60.027896 秒内成功读取 1793/1793 帧，失败 0，实测 29.869446 fps。
- 最大成功帧间隔 0.069013 秒，实际帧为 1920×1080 MJPG。
- 3/3 次重新打开和首帧读取成功。
- 3840×2160 请求回退为 1920×1080，未宣称 4K 能力。

## 遇到的问题

- [[ISSUE-001-摄像头枚举CLI缺少duration属性]]

## 解决过程

- 首次 CLI 枚举因无条件读取子命令专属参数而失败。
- 改为安全读取可选属性并补充回归测试；随后枚举、烟雾测试和正式测试均成功。

## 今日结论

- 当前 Windows 主机可以通过 DirectShow 稳定采集 Insta360 Ace Pro 2 的 1920×1080 MJPG 视频。
- M1 的软件采集和 60 秒稳定性门槛已满足。
- 结果只覆盖当前连接和 60 秒窗口，不代表全天候或长期老化稳定性。
